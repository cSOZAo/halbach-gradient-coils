# Gradient coils — Halbach low-field MRI (pyCoilGen)

Design of gradient coils (Gx, Gy, Gz) for a Halbach-based low-field MRI scanner,
built on top of **pyCoilGen**. The project takes a pyCoilGen wire layout, adds
lead wires, and carves the wire grooves into printable Fusion 360 shell halves
to produce a negative mold for winding.

Everything is driven by a single config object (`coilgen/config.py`) and exposed
through a Tkinter GUI and a CLI.

---

## Hardware constraint (read before touching physics)

- Scanner **B0 is parallel to +Y** (transverse to the bore).
- Gradient fields must be oriented along **Y** as well (the relevant component
  is the one parallel to B0).
- pyCoilGen optimizes **Bz** internally. The cylinder mesh is rotated
  `R_y(π/2)` so the optimized component ends up aligned with the physical
  gradient axis. `Config.internal_axis` maps a physical axis to the pyCoilGen
  internal axis: `x → y`, `y → z`, `z → x`.

## Layout

```
pruebas/
  coilgen/              # consolidated, config-driven package
    config.py           # Config dataclass + per-axis lead presets
    geometry.py         # rotations, internal_field_axis, target-field builder
    fasthenry.py        # cross-platform FastHenry2 binary resolution
    paths.py            # output dirs / unique (n) suffix helpers
    metrics.py          # slope / RMSE / rel-error extraction + metrics.txt
    overlap.py          # wire collision / overlap detection
    gradient.py         # run_gradient(cfg) -> solution, metrics, overlap report
    leads.py            # run_leads(cfg, wire_stl) -> with_leads/coil_open/leads_only
    shell.py            # run_shell(cfg, with_leads_stl) -> shell halves
    sweep.py            # run_tikhonov_sweep(cfg, ...) -> SweepResult
  gui/                  # Tkinter GUI
    main_window.py      # mode selector + shared output-dir field
    pipeline_panel.py   # full pipeline tab
    standalone_panel.py # single-step tab (wire / leads / shell)
    sweep_panel.py      # Tikhonov sweep tab
    runner.py           # worker thread + log redirection
  run_pipeline.py       # CLI: full pipeline
  run_gui.py            # launches the GUI
  assets/
    shells/                 # printable shell halves (g_1a/b, g_2a/b, g_3a/b)
  resultados/            # outputs (gitignored)
  obsolete/              # superseded experiments
    _pre_consolidation/  # the former pipeline/ pipeline_gz/ standalone/ + output_utils.py
                         # (kept pending end-to-end validation of coilgen/; safe to delete
                         #  once you confirm the new package reproduces your Gy result)
```

`coilgen/` finds `pyCoilGen` by adding its parent directory to `sys.path`
(see `coilgen/__init__.py`), so run the entry points from this `pruebas/`
folder.

## Install

Requires Python 3.10+ and the pyCoilGen package (sibling of this folder).

```bash
pip install numpy scipy matplotlib trimesh manifold3d pandas
# scikit-image is needed only if you enable voxel remesh in ShellConfig
pip install scikit-image
# FastHenry2 is optional (inductance metrics); put it on PATH or set
# cfg.fasthenry.bin_path. Without it, R/L are reported as n/a.
```

## Usage

### GUI

```bash
python run_gui.py
```

Three tabs, all of which ask for an output directory at the top of the window:

1. **Pipeline** — gradient axis, dimensions, Tikhonov, levels, wire
   characteristics, layer, custom STL vs autogenerated shell, step toggles,
   and a collision-warning checkbox. Runs gradient → leads → shell in a
   background thread with a live log.
2. **Standalone** — pick one action (generate wire / leads / shell) and supply
   the required input file(s).
3. **Barrido Tikhonov** — dimensions, Tikhonov min/max/num-coarse, fine-adjust
   toggle. Pre-fills the widened Gz range (up to 1 000 000). Results are shown
   in a table and saved as CSV/TXT.

### CLI — full pipeline

```bash
python run_pipeline.py --axis y --tikhonov 2500 --levels 26 --layer 2
python run_pipeline.py --axis z --tikhonov 10000 --layer 3
python run_pipeline.py --skip-gradient            # reuse a previous wire STL
python run_pipeline.py --skip-leads --skip-shell  # gradient only
```

Outputs go to `resultados/pipeline/G{axis}_tk{N}_lvl{M}/` (or `…(2)` on
re-run); each run gets its own subfolder.

### CLI — single step / sweep

```bash
python -m coilgen.gradient --axis y --tikhonov 2500 --output-dir resultados/wire
python -m coilgen.leads path/to/wire.stl --axis y
python -m coilgen.shell path/to/with_leads.stl --axis y --layer 2
python -m coilgen.sweep --axis z --no-fine
```

## Per-axis lead presets

Leads exit along the cylinder bore (±X after `R_y(π/2)`); only the angular
station of the apex changes per gradient axis. Defaults (editable in the GUI):

| Axis | `lead_direction` | `sector_ref_dir` | `sector_angular_half` | spread signs |
|------|------------------|------------------|------------------------|--------------|
| Gx   | `[-1, 0, 0]`     | `[0, 1, 0]`      | 0.35 rad               | `(+1, -1)`   |
| Gy   | `[-1, 0, 0]`     | `[0, 0, 1]`      | 0.35 rad               | `(+1, -1)`   |
| Gz   | `[-1, 0, 0]`     | `[0, 1, 0]`      | 0.35 rad               | `(+1, -1)`   |

These are starting points — the exact Gx/Gz station may need empirical tuning,
but the code no longer falls back silently to an arbitrary apex (the former
Gy-only world-frame filter). If a sector wedge is empty you get a logged
warning rather than a wrong cut.

## Wire collision / overlap check

After `run_gradient`, `coilgen/overlap.py` samples the wire segments and
reports non-adjacent pairs closer than `cfg.overlap_clearance *
cfg.wire.conductor_width`. The CLI prints a warning; the GUI surfaces it.
Raise `cfg.overlap_clearance` to be stricter, or disable with
`--no-overlap-warn` / `cfg.overlap_warn = False`.

## pyCoilGen API rules (hard-won)

- Every key passed to `pyCoilGen(log, arg_dict)` must be registered in
  `sub_functions/parse_input.py` or a plugin's `register_args()` (mesh:
  `build_cylinder_mesh.py`, `create_stl_mesh.py`; export: `export_cad_file.py`).
  Unregistered keys raise `KeyError` immediately.
- `smooth_flag` does **not** exist — smoothing is controlled only by
  `smooth_factor` (>1 enables it).
- `field_shape_function` is **ignored** when `target_field_definition_file !=
  'none'`; the file takes precedence.
- Target-field file format (`.npy` pickle, replaces MATLAB `.mat`):

  ```python
  np.save(path, np.array([{'coords': arr_3xN, 'field_name': arr_N}],
             dtype=object), allow_pickle=True)
  ```

- Extracting results:
  - `solution.solution_errors.combined_field_layout_per1Amp[2]` → realized Bz
    at 1 A [T/A]
  - `solution.solution_errors.target_field_1A.b[2]` → target Bz at 1 A [T/A]
  - `solution.target_field.coords` → target point coords [m], shape (3, N)

## Conventions

- Code, comments, and docstrings in **English**. Units: SI (m, A, T).
- When changing physics, state assumptions about the coordinate frame (mesh vs.
  optimized component vs. physical B0).
- `resultados/` is gitignored. `obsolete/_pre_consolidation/` holds the
  pre-refactor duplicates and can be removed once the new package is validated.
